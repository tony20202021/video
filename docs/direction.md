# Определение направления движения (5_track_direction)

## Задача

Для каждого трека человека определить: **входит домой** (дверь → лифт) или **уходит** (лифт → дверь).

Учитывается, что человек может ненадолго остановиться у лифта — алгоритм смотрит на первую и последнюю четверть трека, а не на мгновенную скорость.

## Схема

```
2_yolo_boxes_files/run_XXX/
  detections.csv     ← x1,y1,x2,y2 каждого человека в каждом кадре
        │
        ▼
  IoU-трекер           связывает боксы между кадрами → треки
        │
        ▼
  Зонный классификатор
    start_cx < door_x[1]     AND  end_cx > elevator_x[0]  →  "home"
    start_cx > elevator_x[0] AND  end_cx < door_x[1]      →  "away"
    иначе                                                  →  "unknown"
        │
        ▼
  directions.csv / directions.json
```

## Почему не нужна ML-модель

- Боксы уже есть в `detections.csv` (выход скрипта 2)
- IoU-трекер работает на чистом Python/numpy
- Зоны задаются вручную по геометрии помещения
- Загружать бинарник не нужно

## Запуск

```powershell
# PowerShell
.\sh\pipeline\5_track_direction.ps1

# Прямой вызов
python scripts/pipeline/5_track_direction.py \
    .output/pipeline/2_yolo_boxes_files/run_20260629_XXX
```

## Настройка зон (опциональный YAML)

Зоны задаются в координатах центра бокса (нормированные 0..1). Если файл не передан — используются значения по умолчанию.

```yaml
tracking:
  zones:
    door_x:     [0.0, 0.30]     # левая треть кадра = дверь
    elevator_x: [0.70, 1.0]     # правая треть кадра = лифт

  tracker:
    iou_threshold: 0.25   # минимальный IoU для совпадения
    max_age:       5      # кадров без совпадения до потери трека
    min_hits:      2      # минимум совпадений для подтверждения
```

Передать: `python scripts/pipeline/5_track_direction.py run_XXX --config zones.yaml`

Зоны по умолчанию: `door_x = [0, 0.30]`, `elevator_x = [0.70, 1.0]`.

## Вывод

```
.output/pipeline/5_track_direction/run_<input_name>/
  directions.csv    — track_id, cam, direction, hits, start_cx, end_cx, n_frames
  directions.json   — то же в JSON
```

Значения `direction`:
| Значение | Смысл |
|----------|-------|
| `home` | входит домой (дверь → лифт) |
| `away` | уходит (лифт → дверь) |
| `unknown` | недостаточно данных или маршрут неоднозначен |

## Ограничения текущей реализации

- Одна камера = один коридор. Если камер несколько, треки не связываются между ними.
- Если два человека идут рядом и боксы сильно перекрываются — трекер может их перепутать.
- Зоны настроены на конкретную планировку. При смене камеры или угла — нужно перенастроить.
