# Каталоги для замеров (методы и гиперпараметры сглаживания)

Справочник: какие каталоги можно «собрать» в корпус для офлайн-замеров методов/гиперпараметров
сглаживания (Viterbi p_stay, окно, жёсткий голос, склейка зон и т.д.) — с оценкой ошибки и **per-class
recall**. Замер идёт офлайн, во временных каталогах, продакшн не трогается.

## Что нужно блоку, чтобы быть измеримым

Для каждого кропа замеру нужны три вещи:
1. **probs модели** — колонки `p_<class>` в `classifications.csv` (или `classifications_smoothed.csv`);
2. **истина** — `labels.json` рядом (формат `{"labels": {<путь>: [<классы>]}}`, читать через
   `common.utils.multilabel.load_labels` — НЕ `len(json)`: верхний уровень обёрнут ключом `labels`);
3. **камера + время** — из имени кропа (`_parse_cam_t`), для сегментации на визиты.

**Измеримое N** = кропы, у которых есть И probs (строка в CSV), И истина (ключ в `labels.json`).

### Надёжность истины — важно для валидности замера

- **`images/<date>/labels.json`** — метки от раскладки классификатора (argmax) с ручными правками
  (`2_label_ui`). Независимы от СГЛАЖИВАТЕЛЯ → корректны для замера методов сглаживания (смещены к argmax
  модели, но это честный референс). **Предпочтительный источник истины.**
- **`smoothed/<date>/labels.json`** — ⚠️ **частично циклична**: сидируется из `smoothed_class` (выход
  сглаживателя) + ручные правки. Мерить сглаживание против выхода сглаживателя = смещение в пользу того
  метода, что породил seed (сейчас — Viterbi/жёсткий голос). Использовать с осторожностью; для чистого
  замера брать `images`-истину.
- Пользователь предупреждал: разметка инференса «вся, но с неточностями». Замер — приблизительный, тренды
  между методами надёжнее абсолютных чисел.

### Рекомендации по сбору корпуса

- **Полный замер** → объединить `v1+v2+v3+v4/images` (35 дат, ~46k измеримых, `images`-истина).
- **ЖКХ (utl) recall** → всегда включать **v2** (955 utilities в 4 датах — плотнее всех; v1/v3 почти без
  ЖКХ). ЖКХ — миноритарный класс, который жёсткий голос топит без склейки зон (см. `ml.md`), поэтому его
  представленность в корпусе критична.
- **Быстрый прогон / кросс-чек** → v3 (9 дат, независимый инференс) или свежий срез v4.
- ⚠️ дата `20260720` есть и в v3, и в v4 — это РАЗНЫЕ прогоны инференса (v3: 46 кропов, v4: 1101).

## Как запустить замер

Паттерн (офлайн, temp-каталоги, прод не трогается): для каждой даты вызвать
`smooth_core.smooth_date(date_dir, GROUPS, out_dir=<temp>, gap=..., p_stay=..., hard_vote=..., merge_zones=...)`,
прочитать `classifications_smoothed.csv` → `{crop: smoothed_class}`, сверить с `_load_truth(labels.json)`:
ошибка = `smoothed_class ∉ truth[crop]`; recall класса C = доля `smoothed==C` среди кропов с истиной `==C`.
Готовый пример свипа методов/гиперпараметров и его результаты — в [ml.md](ml.md) (раздел «Свип
методов/гиперпараметров»).

Локальный прогон одного метода через CLI:
```bash
python scripts/pipeline/3b_smooth_groups.py .data/groups/v3/inference/images \
    --gap 10 --p-stay 0.9 --gate 0 --hard-vote --merge-zones \
    --truth .data/groups/v3/inference/images
```
